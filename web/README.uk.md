# 3D-сторінки

> ⚠️ **Автор — Ihor Ivaniuk (@IBITLAB): ідея, задачі, рішення; виконання — ШІ (Claude Code).** Інженер не перевіряв, машину не збудовано й не випробувано. Повне застереження — у [README.uk.md](../README.uk.md#застереження).

Дві версії однієї інтерактивної сторінки для моделі `scad/excavator_boom.scad`: обертати машину, рухати стрілу, рукоять і ківш, перебудовувати її з будь-яким іншим параметром. Жива версія викладена на GitHub Pages.

| Сторінка | Запуск | Перебудова після зміни параметра | Що потрібно |
|---|---|---|---|
| З сервером | `web/viewer.sh` → `viewer.py` + `viewer/index.html` | ≈ 0.4 с (настільний OpenSCAD) | Python і OpenSCAD; лише українська |
| Без бекенду | `web/viewer-wasm.sh` → `viewer-wasm/` (Vite) | ≈ 2.2 с (OpenSCAD-WASM у браузері) | Node для збирання; дві мови, телефон, AR |

Решта технічних подробиць — у [docs/TECHNICAL.uk.md](../docs/TECHNICAL.uk.md); як сторінки отримують дані (echo `VIEW`, сітки OFF, спільні блоки коду) — у [docs/ARCHITECTURE.uk.md](../docs/ARCHITECTURE.uk.md) і [docs/GEOMETRY.uk.md](../docs/GEOMETRY.uk.md).

## 1. Сторінка з сервером (`web/viewer/`)

```
web/viewer.sh                                   # відкриває http://127.0.0.1:8765/ у браузері (Ctrl+C — зупинити)
python3 web/viewer.py --export файл.html        # статична сторінка без сервера (є в кожній версії: latest/viewer.html)
```

- **Миша**: ліва кнопка — обертання, права або Shift — панорама, коліщатко — масштаб до курсора, подвійний клік по деталі — новий центр обертання. Кнопки виглядів (збоку, ізометрія, зверху, спереду, вписати) і перемикач перспектива / ортогонально.
- **Кути стріли, рукояті, ковша** рухають модель миттєво: позу складає сама сторінка за тими самими формулами, що й функції `pt_*()` моделі, з точок, які модель друкує в `echo(VIEW = …)` (звірено з echo моделі: положення зуба і довжини циліндрів збігаються до 0.1 мм). Межі повзунків — з ходу циліндрів; біля кожного кута видно довжину циліндра і використаний хід. Якщо зняти «обмежувати ходом циліндрів», циліндр поза ходом червоніє. Є готові пози і «цикл копання».
- **Усі інші параметри** (групи Customizer читаються прямо з `.scad` — окремого списку немає) ідуть на локальний сервер: він запускає OpenSCAD паралельно для 12 деталей у власних системах координат і віддає сітки з кольорами (формат OFF). Змінені параметри підсвічуються; «Копіювати зміни» дає готові рядки для вставки в `.scad`; «Перечитати модель» підхоплює правки файлу. Попередження моделі (`!!!` — мертва точка важелів, недосяжна довжина циліндра) показуються на екрані.
- Сервер слухає лише 127.0.0.1; значення з браузера приводяться до типів зі схеми (числа, булеві, переліки), довільний текст в OpenSCAD не потрапляє. three.js завантажується з CDN (jsdelivr) — потрібен інтернет.

## 2. Сторінка без бекенду: OpenSCAD-WASM у браузері (`web/viewer-wasm/`)

```
cd web/viewer-wasm && npm install      # залежності: three, openscad-wasm-prebuilt (OpenSCAD 2025.01 + Manifold, 11 МБ), vite
npm run dev                              # http://localhost:8766/ — правка scad/excavator_boom.scad одразу перезавантажує сторінку
npm run build                            # статичний сайт у dist/ (≈12 МБ): класти на будь-який статичний хостинг
npm run preview                          # переглянути зібраний dist/ локально
npm test                                 # димовий тест без браузера
# те саме однією командою з кореня: web/viewer-wasm.sh [build|preview|phone|test]
# phone — зібрати й відкрити доступ із телефона в тій же Wi-Fi (Vite інакше слухає лише 127.0.0.1)
```

- Та сама сторінка й те саме керування, що у версії з сервером (вона лишилась: `web/viewer.sh`), але **OpenSCAD працює у веб-воркері браузера**; Python і встановлений OpenSCAD не потрібні. Модель вшивається у сторінку під час збирання (`?raw`-імпорт), параметри Customizer розбирає JavaScript (`src/schema.js`).
- Один запуск рушія на зміну параметра: модель у режимі `part="view_all"` кладе всі 12 деталей зі зсувом по Y, сторінка розрізає сітку назад (`src/offmesh.js`). Виміряно у Chrome: перший старт ≈ 5 с (завантаження рушія), **перебудова після зміни параметра ≈ 2.2 с**; кути, як і раніше, миттєві. Для порівняння: версія з сервером перебудовує за ≈ 0.4 с.
- **Дві мови: українська та англійська.** Перемикач `UK | EN` у шапці панелі; мова береться з `?lang=en` в адресі, далі з пам'яті браузера, далі з мови самого браузера. Переключення лише перемальовує підписи — OpenSCAD не перезапускається, кути, прапорці й змінені параметри лишаються на місці. Перекладено і назви груп та описи всіх 103 параметрів моделі: англійські тексти лежать у `src/i18n.js`, українські беруться прямо з коментарів `.scad`, тож модель лишається єдиним джерелом правди. `npm test` перевіряє, що словник не розійшовся з моделлю (кожна група і кожен описаний параметр мають переклад) і що обидві мови мають однакові ключі. Попередження, які друкує сама модель (`!!!`), лишаються українською — вони приходять з `echo()` у `.scad`. Сторінка з сервером (`web/viewer.sh`) — лише українська.
- **З адреси сторінка читає лише мову** (`?lang=en`). Початкові значення параметрів колись задавалися там само — прибрано навмисно: це був єдиний шлях, яким значення з чужого посилання потрапляло у текст моделі OpenSCAD. Модель вшивається у сторінку під час збирання, і **відкрити в ній чужий `.scad` теж не можна** — це прибрано навмисно: текст такого файлу став би назвами груп, описами й попередженнями в панелі, тобто чужими даними в сторінці, яка живе на спільному домені GitHub Pages.
- **На телефоні й планшеті панель — шухляда знизу**, у трьох станах: згорнута (тільки смужка-ручка з вильотом і висотою зуба — модель на 93 % екрана), робоча (три повзунки кутів і готові пози) і повна (ще й ракурси з прапорцями видимості). Тягнеться пальцем за ручку, дотик по ручці згортає й розгортає. Розкладку вмикає не лише ширина, а й `pointer: coarse`: телефон, повернутий набік (844 px), і планшет у портреті (768 px) інакше діставали б бічну колонку на пів екрана. Параметри моделі, пристрої та ракурси для рендерів на дотикових пристроях сховані — з телефона їх не міняють. Попередження про ШІ згорнуте за замовчуванням **скрізь** — видно лише рядок-підсумок, решту користувач розкриває сам; на телефоні воно живе під значком ⚠ у ручці, поруч із кнопкою згортання й перемикачем мови, і розкривається карткою поверх моделі. Ручка «липне» до верху панелі, тож згорнути й розгорнути можна з будь-якого місця прокрутки — і позиція прокрутки при цьому зберігається. Унизу панелі — нотатка про те, чого на телефоні немає. Готові види на телефоні стоять **іконками в рядку заголовка «Кути»** — куб в ізометрії з підсвіченою гранню, на яку дивишся, як у CAD. Так увесь набір ракурсів на першому екрані й не займає окремого блоку; на комп'ютері поруч з іконкою лишається підпис. Проєкція — не вид, а стан, тож вона стоїть окремою групою за роздільником, має круглу форму замість прямокутної, і її іконка показує поточне: у перспективі сторони кадру сходяться, в ортогональній — паралельні.
- **Знімок кадру.** Кнопка «⤓ Зберегти PNG» у розділі «Вигляд» віддає поточний кадр разом зі смугою підпису: виліт зуба, глибина чи висота над землею, кути стріли, рукояті й ковша, нахил отвору та висоту осі A над землею, від якої все це відлічується. Знімок екрана цього не дає — він тягне за собою всю панель, а числа лишаються дрібними. На телефоні кнопка викликає системне «Поділитися», тож картинку можна одразу покласти у фото або надіслати.
- **Легенда кольорів** під прапорцями видимості: труби, пластини й накладки, гідроциліндри, ківш, втулки з пальцями. Кольори взято не зі стелі, а з самих викликів `color(...)` у моделі, і `npm test` перевіряє, що вони не розійшлися.
- **«Що з чим зварене»** — окремий прапорець, який перефарбовує машину за ЖОРСТКИМИ ТІЛАМИ: стріла вся одним кольором, рукоять другим, ківш третім, коромисло, тяга, гільзи й штоки — своїми, а пальці яскраво-червоним. Тоді однаковий колір означає «зварено в одне», межа кольорів — шарнір, а червона крапка — вісь, навколо якої крутиться. Звичайна палітра каже, З ЧОГО деталь зроблена, ця — ЩО РУХАЄТЬСЯ відносно чого; це різні питання, тому й різні режими. Кольори підібрано не на око: зміряно ΔE в CIE Lab на одинадцяти парах, які справді дотикаються в шарнірах, мінімум — 30.
- **Дотик по деталі підсвічує все, що з нею зварене**, решта машини гасне. Питання «а що рухається разом із цим?» має відповідь за один дотик, без режимів. Повторний дотик або дотик по порожньому місці знімає підсвітку; перетягування ковша її не чіпає.
- **Смужка завантаження рушія.** 11 МБ їхали мовчки, і на повільному каналі це виглядало як зависання. Тепер сторінка тягне файл сама, потоково, і показує «4.2 / 11 МБ» — рівно один раз, без подвійного завантаження. Глибина зуба нижче землі в HUD виділена кольором: це головне число сторінки.
- **Клавіші (лише з клавіатурою):** `1`–`6` — готові види, пробіл — цикл копання. На дотикових пристроях не вішаються зовсім.
- **AR у справжньому розмірі (WebXR).** На телефоні з Android і Chrome (потрібні сервіси ARCore) у куті над моделлю з'являється кнопка «◎ AR 1:1». Машина стає на підлогу через камеру: коло — точка на землі під віссю A (основа стріли), вісь — на висоті «вісь A над землею», стріла — праворуч, тобто машину видно збоку. Так її ставлять на край ями й «копають» у неї; ↺ ↻ повертають навколо осі A. Масштаб справжній (ARCore міряє простір метрично, похибка — кілька відсотків), машину можна обійти, а три повзунки й «▶ цикл» рухають стрілу, рукоять і ківш так само, як на екрані: позу рахує той самий код, OpenSCAD не перезапускається. Масштаб 1:1 (надворі) або 1:5 (на столі), поворот по 15°, «Перенести» ставить машину в іншому місці. Там, де браузер AR не вміє (комп'ютер; iPhone — у Safari немає WebXR для AR), кнопки немає. Потрібні https (GitHub Pages) або localhost; адреса з `web/viewer-wasm.sh phone` — звичайний http у Wi-Fi, тому до публікації в Chrome на телефоні: `chrome://flags/#unsafely-treat-insecure-origin-as-secure` → вписати адресу, яку друкує скрипт (`http://АДРЕСА-КОМПʼЮТЕРА:8767`) → Enabled → Relaunch; після тестів повернути Default. Переадресація порту кабелем (`chrome://inspect` → Port forwarding) на деяких телефонах так і не показує запит на дозвіл налагодження — прапорець не потребує ні кабелю, ні програм. Без справжнього телефона перевіряється лише логіка: `probe.mjs --pre` з підставним `navigator.xr` (кнопка, запит сеансу, повідомлення про відмову) і `__ARUI__()` — накладка без сеансу.
- **AR: кімната — затуляння, площини, сітка, зіткнення.** Сеанс просить три необов'язкові можливості WebXR. Кожна вмикається лише там, де браузер її дав; що саме дано, видно дрібним рядком під підказкою («глибина ✓ · площини — · сітка —»). **Глибина** (`depth-sensing`, Chrome на Android з ARCore Depth — більшість сучасних телефонів): справжні предмети затуляють машину, тож стріла ховається за стовпом, а не малюється поверх нього. Вмикає й вимикає кнопка ◐. **Площини** (`plane-detection`; у Chrome на Android — за прапорцем `chrome://flags/#webxr-incubations`, у Quest — зі сканування кімнати) і **сітка приміщення** (`mesh-detection`, Quest 3; Chrome на Android її не дає) малюються напівпрозоро: стіни синім, горизонтальні поверхні зеленим, предмети помаранчевим. Кнопка ▦ ховає їх, але зіткнення рахуються й тоді. **Зіткнення** перевіряються десять разів на секунду: для кожного тіла машини беруться до 120 його вершин, і зіткненням вважається, якщо відрізок від шарніра тіла (A, B, E, пальці циліндрів) до вершини перетинає стіну, стелю, стіл чи предмет або вершина ближча до них за 3 см. Тоді тіло червоніє, у точках зіткнення з'являються червоні кульки (їх видно й без накладки), зверху — плашка «⚠ Зіткнення: стіна — стріла», телефон коротко вібрує. Кнопка ⚠ вимикає перевірку зіткнень (і гасить позначки), коли треба навмисно провести машину крізь стіну; кімната відстежується й далі, тож увімкнення діє одразу. Підлога, на якій стоїть машина, не рахується: ківш і має копати нижче неї. Вершини — вибірка, тож тонкий предмет між ними (ніжка стільця) може проскочити. **Зліпок кімнати** (`src/keep.js`). ARCore зливає сусідні площини в одну й губить ті, від яких камера відвернулася, а для зіткнень це означало б «стіни немає». Тому зникла площина лишається тінню зі штриховим контуром. Якщо її знову покрила жива площина (та сама площина, щонайменше 60 % усередині), це злиття або повторна поява: тінь прибирається, а жива площина отримує ще одне підтвердження. Якщо за 5 с ніхто не покрив, площина, що вже з'являлася повторно, або велика (≥ 1 м²) і видна від 5 с, лишається до кінця сеансу із суцільною заливкою. Решта вважається шумом і прибирається. Залишену площину прибирає лише карта глибин: якщо шість разів поспіль (1.5 с) крізь неї видно щонайменше на 25 см далі. Тіні беруть участь у перевірці зіткнень. У рядку під підказкою видно «зліпок N, чекають M». Зліпок живе один сеанс: простір наступного сеансу починається з іншої точки. **Скан кімнати** (кнопка ▤, `src/scan.js`, типово вимкнено). Поки кнопка ввімкнена, кадри глибини зливаються в одну 3D-модель кімнати. Кожна точка глибини прив'язується до простору сеансу позою камери, яку трекінг ARCore дає для цього кадру. Це той самий трекінг, що ставить машину на підлогу, тож площини для цього не потрібні. Метод той самий, що в KinectFusion: розріджена сітка вокселів по 5 см (блоки 8×8×8 створюються лише там, де бачили поверхню). У кожному вокселі зберігається усічена знакова відстань до поверхні (±15 см) і вага. Чотири рази на секунду кадр із 96 променів уздовж довшого боку додається зваженим середнім, тож шум окремих кадрів усереднюється. Уздовж половини променів простір перед поверхнею вичищається, тому людина, що пройшла, зникає з моделі. Раз на секунду змінені блоки перебудовуються методом Surface Nets. Модель ділиться на шматки по 1.6 м, і перебудовуються лише ті шматки, що змінились. Вона малюється заливкою із сіткою, кольорами кімнати за нахилом. Об'єм передається чотирма способами, і всі вони беруться з того самого поля відстаней. Гладкі нормалі — з його градієнта, тож грані не «рябіють». Затінення кутів (ambient occlusion) темнить заглибини: якщо крок уздовж нормалі натрапляє на іншу поверхню раніше, ніж мав би, поруч заглибина, як-от кут стіни й підлоги чи місце під столом (близько 12 см, далі поле нічого не знає). Поверхні, повернуті боком до погляду, темніші, наче на камері ліхтар. Далекі поверхні трохи тьмяніші. Останні два способи діють лише на скан, не на машину. Повзунок «Скан» у панелі задає прозорість. Діапазон — від ледь видимої до суцільної, і суцільна модель закриває зображення камери: видно лише модель, а реальність проступає тільки там, де ще нічого не відскановано. Повторне натискання ▤ ставить скан на паузу, а модель лишається до кінця сеансу. У рядку під підказкою видно «скан N тис. △». Пам'ять обмежено 20 000 блоками, це близько 50 МБ на вокселі. Кімната 4 × 5 м займає близько 850 блоків, тож цього вистачить на двадцять таких кімнат. Межа стоїть лише для того, щоб дуже довгий скан не з'їв усю пам'ять вкладки. У зіткненнях скан поки не бере участі. Межі: глибина надійна лише до 4 м, а якщо трекінг «попливе», модель зсунеться разом із ним. Окуляри без накладки (Quest): курок ставить машину і знову переводить у пошук місця, бічна кнопка вмикає цикл копання. Геометрія зіткнень — `src/room.js`, без DOM; її числами перевіряє `npm test`. `__ARSCAN__(z)` сканує синтетичну кімнату-коробку з 16 кадрів глибини (усі вершини мають лягти в межах 3 см від її стін) і проганяє зліпок для стіни на `z` (−3 — лишається, −2 — карта глибин її прибирає). `__ARSIM__(x)` ставить справжню модель 1:1 перед стіною на відстані x м і повертає зачеплені тіла (стіна за 1 м — стріла й циліндр рукояті, за 6 м — нічого). Затуляння, площини й сітку перевірити можна лише на справжньому пристрої.
- **Машину можна тягнути за ківш.** Хапаєш корпус ковша — за пальцем іде вся стріла: сторінка розв'язує зворотну задачу й підбирає кути стріли та рукояті. Хапаєш зуби — ківш підвертається навколо своєї осі, стріла стоїть. Працює і мишею, і одним пальцем. Розв'язок точний і без ітерацій: шарнір B лежить на перетині двох кіл, і `npm test` жене пряму задачу крізь зворотну туди й назад (похибка зуба — 10⁻¹² мм). Недосяжна ціль не «заморожує» руку: вона йде за пальцем до межі робочої зони, а обмеження ходом циліндрів лишається чинним. Замок «Не крутити камеру» вимикає обертання сцени зовсім — тоді тягнути можна з будь-якого місця, не цілячись у ківш. На телефоні він стоїть у ручці шухляди поруч зі значком ⚠ — ручка прилипла до верху панелі й видна завжди, тоді як ряд видів у заголовку прокручується. На комп'ютері замок плаває над канвою в лівому нижньому куті, поруч із тим, чим керує. Замкнений — помаранчевий. Як цим керувати, написано в картці під значком ⚠ поруч із попередженням про ШІ — там воно **завжди**, і на телефоні, і на комп'ютері. Крім того, тому, хто тут уперше, те саме показує плашка над моделлю: вона тримається, доки він не зробить **дві** операції (після однієї ще не видно, що жест повторюваний), і зникає по хрестику. Далі текст лишається за значком.
- **Публікація на GitHub Pages**: `.github/workflows/pages.yml` збирає сторінку й викладає її при кожному push у `main` (увімкнути один раз: Settings → Pages → Source: GitHub Actions). Перед збиранням workflow ганяє `npm test`, щоб зламана модель не потрапила на сайт, і кладе поруч `LICENSE` та `THIRD-PARTY.md` — цього вимагає GPL, бо сторінка вшиває сам OpenSCAD. Ті самі посилання є внизу панелі сторінки.
- **Картка посилання**: теги Open Graph у `<head>` файлу `index.html` (назва й опис англійською) і `public/og.png` (1200×627, ізометричний рендер) дають LinkedIn, Facebook і месенджерам картку з картинкою. Адреси там абсолютні, тож при переїзді сайту їх треба змінити. Після зміни LinkedIn тримає стару картку, доки адресу не перечитати в його Post Inspector.
- `dist/` не відкривається подвійним кліком (сторінка, відкрита як локальний файл, не може запустити модульні воркери) — потрібен будь-який статичний веб-сервер (`npm run preview`, GitHub Pages тощо). `node_modules/` і `dist/` у git не потрапляють.
- Рушій у браузері старіший (2025.01) за настільний OpenSCAD (2026.09). `npm test` перевіряє, що він будує модель без попереджень, усі деталі непорожні, поза з JavaScript збігається з echo моделі, а блок складання пози однаковий в обох версіях сторінки.

### Кольори в AR

| Синє напівпрозоре | Стіна: вертикальна площина, стіна в сітці приміщення або вертикальна частина скану |
| Зелене напівпрозоре | Горизонтальна поверхня: підлога, стіл, стеля |
| Помаранчеве напівпрозоре | Решта: предмети в сітці приміщення, похилі частини скану |
| Штриховий контур, ледь видима заливка | Площина, яку браузер загубив. Вона до 5 с чекає рішення (зліпок) |
| Штриховий контур, звичайна заливка | Загублена площина, залишена до кінця сеансу |

## 3. 3Dconnexion SpaceMouse у браузері

Обидві сторінки (з сервером і WASM) керуються 3D-мишею без плагінів; блок коду однаковий в обох (`//<spacemouse>`).

| Браузер | Шлях | Що зробити |
|---|---|---|
| **Chrome / Edge / Opera** | WebHID — сторінка сама читає звіти миші | «Вигляд» → кнопка **SpaceMouse** → у вікні браузера «…хоче підключитися до HID-пристрою» вибрати мишу (або «3Dconnexion Universal Receiver») → «Підключити». Вікно з'являється лише після кліку — це вимога браузера. Дозвіл видається **окремо на кожну адресу** (`127.0.0.1:8765`, `localhost:8766`, `localhost:8767` — три різні) і діє, доки миша ввімкнена і браузер відкритий; якщо миша повідомляє серійний номер, Chrome пам'ятає дозвіл назавжди і сторінка підхоплює мишу сама (також після повторного вмикання в USB). Якщо ні — після перезапуску браузера кнопку треба натиснути ще раз. Відкликати: значок ліворуч від адреси → «Налаштування сайту» → HID-пристрої. Потрібен захищений контекст: https, `localhost` або локальний файл (перевірено: Chrome відкриває WebHID і для статичного `viewer.html` з диска). |
| **Firefox** | Gamepad API (WebHID у Firefox немає) — миша видна як 6-осьовий «геймпад» | Нічого натискати не треба: **порухайте ковпачок або натисніть кнопку миші**, коли вкладка у фокусі, — статус зміниться на «підключено (Gamepad API)». Перевірити, чи Firefox бачить мишу: `about:support` → або будь-який «gamepad tester». Цей самий шлях працює і в Chrome як запасний. |
| Safari | — | немає ні WebHID, ні доступу до 3D-миші через Gamepad API |

- **Керування** (режим «об'єкт у руці»): ковпачок праворуч/ліворуч і вгору/вниз — зсув; до себе / від себе — масштаб; скрут — обертання довкола вертикалі; нахил до себе / від себе — підйом камери. Кнопка 1 — «Вписати», кнопка 2 — наступний стандартний вигляд. Повзунок чутливості та три прапорці інверсії (зсув / масштаб / обертання) зберігаються в браузері. Крен (нахил убік) свідомо не використовується: вертикаль моделі лишається вертикаллю.
- **Ківш мишею (лише WASM-сторінка)**: коли ввімкнено «Не крутити камеру», миша вже не рухає камеру, а веде **ківш**. Оператор керує самим ковшем, а стріла, рукоять і ківш рахують свій рух разом, тож ківш іде, не повертаючись (`armFromBucket` у `src/ik.js`, точний розв'язок без ітерацій). Від себе / на себе — зуб строго вперед / назад, натиснути / потягнути — вниз / вгору, нахил уперед — підгорнути (зуби вгору до себе), назад — висипати: ківш повертається навколо пальця E, стріла стоїть. Перемикач у «Пристроях» задає систему відліку: **від бази** — оператор стоїть біля осі A і дивиться вздовж стріли, тож вліво / вправо, скрут і крен нічого не роблять (поворот колони ще не спроєктовано); **від камери** — осі ковпачка збігаються з осями екрана, і все, що йде вглиб екрана чи вбік від площини машини, відкидається. Упор котрогось циліндра не спиняє ківш: спершу ківш іде з тим самим кутом до рукояті, потім ковзає вздовж упору лише горизонтально чи лише вертикально. Недосяжну точку ківш не перескакує, а зупиняється перед нею.
- **macOS:** якщо встановлено драйвер 3Dconnexion, `3DconnexionHelper` відкриває мишу монопольно (у `ioreg` клієнт Chrome має `ClientSeized = Yes`), тому кнопка SpaceMouse дає «Failed to open the device». Рішення: `tools/dev/spacemouse-driver.sh off` → натиснути кнопку ще раз → у вікні вибрати саме **свою мишу** (рядки «3Dconnexion Virtual Mouse / Virtual Data» — віртуальні пристрої драйвера, не вони). Повернути драйвер для CAD-програм: `tools/dev/spacemouse-driver.sh on` (після входу в систему він стартує сам). **Автоматично:** `tools/dev/with-spacemouse.sh <команда>` вимикає помічник перед стартом і вмикає його знову, щойно команда завершиться з будь-якої причини (Ctrl+C, закриття термінала, помилка) — `tools/dev/with-spacemouse.sh web/viewer.sh`, а для WASM-сторінки `npm run dev:sm` / `npm run preview:sm`. Якщо помічник до старту не працював, він і не запускається. Звичайні `npm run dev` / `preview` драйвер не чіпають.
- **Драйвер 3DxWare** може заважати: на Windows/macOS він сам шле у вікно браузера прокрутку й клавіші (рух «двоїться») або тримає пристрій. Якщо так — у 3Dconnexion Home вимкніть мишу для браузера або закрийте драйвер на час роботи зі сторінкою. Для Firefox на Windows/macOS драйвер зазвичай **треба** закрити, інакше «геймпад» не з'явиться.
- **Linux**: для Chrome/WebHID потрібне право на `/dev/hidraw*` — правило udev `SUBSYSTEM=="hidraw", ATTRS{idVendor}=="256f", MODE="0660", TAG+="uaccess"`; Firefox бере мишу через `/dev/input/js*` без налаштувань (spacenavd не потрібен і має бути вимкнений, якщо захоплює пристрій).
- **Що перевірено**: логіка навігації — автоматично в headless Chrome з підставними пристроями обох типів (`web/viewer-wasm/test/spacemouse.mjs`: звіти 1/2/3, 12-байтний звіт нових моделей, кнопки, Gamepad API, ківш при замку камери в обох системах відліку). **Зі справжньою мишею не перевірялося** (її не було під час розробки): якщо якась вісь їде не туди — увімкніть відповідну інверсію; якщо миша взагалі не реагує у Chrome — відкрийте `chrome://device-log` і подивіться, чи приходять звіти HID.
- Офіційний шлях 3Dconnexion (SDK «3DxWare for Web», WebSocket до драйвера — так працює Onshape) тут не використано: він вимагає встановленого драйвера і ліцензійного SDK, зате працює однаково в усіх браузерах. Якщо WebHID/Gamepad не влаштують — це наступний варіант.
