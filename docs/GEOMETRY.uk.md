# Геометрія: сторінка, метал, друк

Звідки 3D-сторінки беруть геометрію, чим STL для друку відрізняються від моделі для металу і як влаштований формат OFF, яким модель передає сітки у браузер. Загальна карта коду — [ARCHITECTURE.uk.md](ARCHITECTURE.uk.md).

## 1. Хто з чого будує

| Споживач | Джерело | Вихід |
|---|---|---|
| WASM-сторінка (`web/viewer-wasm/`) | `scad/excavator_boom.scad` — метал 1:1, зварні тіла | OFF у пам'яті браузера |
| Сторінка з сервером (`web/viewer.py`) | та сама модель | OFF на кожне тіло → JSON |
| `tools/build_version.sh` | та сама модель | STL 1:1 у `latest/stl/` |
| `print3d-parts/make.sh` | `print3d-parts/parts.scad` (модель як бібліотека) | STL 1:5, по компоненту на файл |

Сторінки набору для друку не використовують і STL не створюють.

## 2. WASM-сторінка

- **Модель вшито.** Vite вкладає текст `scad/excavator_boom.scad` (і `scad/brand/*.scad`) у збірку через `?raw`. Інших джерел `.scad` сторінка не має.
- **Кути — без OpenSCAD.** Позу стріли, рукояті й ковша складає JavaScript (блок `//<pose>`) з точок шарнірів, які модель надрукувала в `echo(VIEW = …)`.
- **Решта параметрів — перебудова.** Змінений параметр іде у веб-воркер як `-D назва=значення`. Воркер запускає OpenSCAD-WASM з `part="view_all"`, отримує один OFF-файл, розрізає його на тіла ([розділ 5](#5-як-в-одному-файлі-вміщаються-12-тіл)) і повертає сітки сторінці.
- **Зміни живуть лише в браузері.** На диск нічого не пишеться. Щоб параметр потрапив у STL для металу чи для друку, його вписують у `.scad` (кнопка «Копіювати» дає готові рядки) і перезбирають версію або набір.

## 3. Друк проти металу

Набір — обгортка `print3d-parts/parts.scad`: `include` моделі з `part="none"`, у самій моделі не змінено жодного рядка. Форма деталей та сама, відмінності додає обгортка:

| Що | Метал (модель) | Друк (обгортка) |
|---|---|---|
| Масштаб | 1:1 | 1:5 (найдовша труба 1050 мм → 210 мм, вміщується на стіл 250 мм) |
| Поділ | зварні вузли | кожен компонент окремо: труба, пластина, втулка, палець |
| Положення | у системі вузла | покладено найменшим розміром догори: вісь і кут з `parts.tsv` |
| Пальці | номінальний діаметр | тонші на 0.40 мм (зазор), з голівкою; отвори вузлів не змінюються |
| Гідроциліндр | суцільний корпус | глухий канал під шток, зазор 0.35 мм |
| Логотип | наліпка, у STL його немає | виїмка на гранях; місця з моделі (`brand_marks`), глибина — з обгортки |
| Лише в наборі | — | пальці з голівкою, кільця, плити колони, розрізний циліндр — тими самими виразами, що в моделі; числа збігаються з `echo(BOM_*)` |

## 4. Формат OFF

OFF (Object File Format) — текстова сітка. Це давній відкритий формат програми Geomview (початок 1990-х); його читають MeshLab і CGAL, у ньому зберігають набори моделей ModelNet і Princeton Shape Benchmark. OpenSCAD експортує в нього штатно (`-o файл.off`) і в нових версіях пише колір кожної грані; у STL кольору немає. У цьому проєкті придумано лише пакування 12 тіл в один файл і розрізання назад ([розділ 5](#5-як-в-одному-файлі-вміщаються-12-тіл)); обидва парсери читають тільки те, що пише OpenSCAD: грані з кольором, без кольорів вершин і нормалей. Приклад — вивід `openscad -o t.off` для двох кубів різного кольору (скорочено):

```
OFF                     ← підпис формату
16 24 0                 ← вершин, граней, ребер (ребра не пишуться, завжди 0)
0 0 0                   ← вершина 0: x y z, мм
0 10 0                  ← вершина 1
…                       ← усього 16 рядків вершин
3 0 3 1 229 153 25      ← грань: 3 вершини, індекси 0 3 1, колір R G B
3 9 0 1 229 153 25
…
3 4 7 5 48 96 160       ← грань другого куба, інший колір
```

| Частина | Зміст |
|---|---|
| Шапка | `OFF` і три лічильники: настільний рушій пише їх наступним рядком, WASM — у тому самому (`OFF 8 6 0`); обидва парсери приймають обидва варіанти |
| Вершини | кожна один раз, мм, система координат моделі |
| Грані | `n`, далі `n` індексів вершин, далі (необов'язково) колір. Настільний рушій пише трикутники, WASM — і багатокутники (грань куба — один чотирикутник `4 …`); парсер розбиває кожну віялом `0, t, t+1` |
| Колір | ціле RGB 0–255 з `color(...)` моделі: `[0.9,0.6,0.1]` → `229 153 25`. Прозорість не пишеться. Без кольору — типовий `230,200,60`. Серверний парсер приймає й дробовий 0–1 |

**Чому OFF, а не STL.** У STL немає кольору, а сторінка фарбує деталі за матеріалом і роллю. STL ще й повторює кожну вершину в кожному трикутнику, тож він утричі більший. 3MF кольори має, але це zip з XML — зайва робота для воркера.

**Чому не glTF.** OpenSCAD його не пише. Що вміють обидва рушії (перевірено експортом кольорового куба):

| Формат | Настільний 2026.09 | WASM 2025.01 (сторінка) |
|---|---|---|
| OFF | є, з кольором граней | є, з кольором граней |
| OBJ | є (колір — в окремому `.mtl`) | є |
| 3MF | є | немає (файл не створюється) |
| glTF / GLB | немає | немає (`Invalid suffix glb`) |

Конвертувати OFF у glTF для сторінок немає сенсу: сітка не йде мережею (воркер → сторінка в одній вкладці, сервер — localhost), позу складає JavaScript, а three.js однаково перетворив би glTF на ту саму `BufferGeometry` з групами. glTF знадобився б лише для експорту назовні (Blender, `<model-viewer>`, AR).

## 5. Як в одному файлі вміщаються 12 тіл

`part="view_all"` кладе i-те тіло зі списку `view_parts` у його власній системі координат, зсунуте на `i · view_spacing` (5000 мм) по Y. Список і крок модель друкує в `echo(VIEW = …)` (ключі `parts`, `spacing`). `web/viewer-wasm/src/offmesh.js` розрізає файл назад:

1. Номер тіла вершини — `round(y / spacing)`; зсув віднімається, вершина повертається у власні координати тіла.
2. Грань іде до тіла своєї першої вершини і там — у групу свого кольору; індекси перенумеровуються всередині тіла.
3. Результат для кожного тіла: `{ pos: Float32Array [x,y,z,…], groups: [{ color: [r,g,b], idx: Uint32Array }] }`. Буфери передаються з воркера без копіювання (transfer). У three.js тіло — одна `BufferGeometry` з групою індексів і матеріалом на кожен колір.

**Умова:** кожне тіло має бути менше за половину кроку (2500 мм) уздовж Y, інакше вершини потраплять до сусіда. Тіла машини — сотні міліметрів завширшки.

Сторінка з сервером працює інакше: 12 процесів OpenSCAD пишуть по OFF на тіло, без зсуву. `viewer.py` розбирає їх так само і віддає в JSON тієї ж структури `{pos, groups}`, лише звичайними масивами.
