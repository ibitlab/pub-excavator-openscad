# Безпека сторінок

Усе тут — з розбору, зробленого на цьому проєкті. Кожна діра нижче **підтверджена
запуском**, а не вичитана очима. Повний розбір із доказами — `temp/url-security-analysis.md`.

## Чотири правила

1. **Розмітка не будується з даних.** `textContent`, `createElement`, `new Option(текст)`,
   властивості (`el.title`, `g.label`, `inp.min`). Ніяких шаблонних рядків із `${дані}`.
2. **Вхід не «чиститься», а перевіряється за схемою.** Збирай НОВИЙ об'єкт із дозволених
   полів; усе, що не підійшло, просто зникає.
3. **`Object.hasOwn`, ніколи `in` і ніколи голе індексування** для пошуку в об'єкті-словнику.
4. **Сторінки не приймають чужих файлів.** Модель вшивається збіркою, інших джерел немає.

## Що вважати чужим текстом

Не тільки те, що прийшло з мережі. У цьому проєкті чужим є:

| Джерело | Куди тече |
|---|---|
| `?назва=значення`, фрагмент `#…` | `values`, далі у **текст `.scad`** і в поля форми |
| назви ракурсів (`localStorage`, `views.json`) | список у панелі |
| текст `.scad`: назви груп `/* [ … ] */`, описи-коментарі, варіанти `// [a, b]` | вся панель параметрів |
| `echo("!!! …")` моделі | попередження в HUD |
| ім'я відкритого файлу | підпис над панеллю |

Назва параметра свого часу вціліла випадково: регулярка схеми — `\w+`. На таке не покладайся.

## Чому ручне екранування не рятує

Воно залежить від контексту, а контекст змінюється при наступній правці:

| Куди вставляєш | Чого досить | Де ламається |
|---|---|---|
| вміст елемента | екранувати `<` | завтра це стане атрибутом |
| атрибут у лапках | `<` і `"` | зняв лапки — треба ще пробіл, `=`, backtick |
| `href` / `src` | **екранування не діє** | `javascript:`, `data:` |
| всередині `<script>` | інша схема цілком | `</script>` у рядку |

Ми на цьому й спіймалися: `vjFill` екранував лише `<`, і у `<option>` цього справді
вистачало — але це випадковість контексту, а не захист.

Та сама родина стоків, про яку забувають: `insertAdjacentHTML`, `outerHTML`,
`document.write`, `<template>.innerHTML`.

Якщо розмітка з даних таки потрібна — санітайзер (`DOMPurify`, `Element.setHTML()`),
ніколи свій регексп: чорний список тегів не працює.

## Діри, які вже були

**`?view=constructor` вішав ОБИДВІ сторінки.** `VIEWS` — звичайний об'єкт, тому
`'constructor' in VIEWS` істинне через прототип, а `VIEWS['constructor']` — функція.
`setView()` падав, виняток тонув у `try/catch` навколо `init()`, у консолі порожньо,
`window.__READY__` не наставав. Найдешевша з усіх: досить **надіслати посилання**.

**`byName[k]` без `hasOwn`** у розборі адреси: `?__proto__=1` сторінку не ламав, бо
значення далі відсіювалося як нечисло — тобто тримався на випадковості, а не на захисті.

**Рядкові параметри з адреси не звірялися з `p.options`.** До `.scad` не доходили
(ловив `scadLiteral`), але замість «значення проігноровано» користувач діставав
зламану збірку. У моделі рядкових параметрів немає — тому це легко не помітити
при наступній зміні моделі.

**XSS із виконанням коду через «Відкрити .scad…».** Кнопка брала довільний файл із
диска, і його текст ставав назвами груп, описами, варіантами й `echo`-попередженнями
у панелі — усе через `innerHTML`. Плюс ім'я файлу. Перевірено: `window.pwned = 3`,
три впроваджені теги. Кнопку прибрано; повертати не можна.

## Як це перевіряти

**Ознака — число, а не вигляд.** «Подивився, наче нормально» тут не працює взагалі.

```js
// у сторінці
window.pwned                                   // лічильник із onerror у payload
document.querySelectorAll('#side img, #side script, #side svg').length
document.querySelector('#hud .w').innerHTML    // має містити &lt;img, а не <img
({}).polluted !== undefined                    // прототип не зачеплено
```

Обов'язковий набір проб по адресі (обидві сторінки): `?view=constructor`,
`?view=toString`, `?__proto__=1`, `?boom_L1=1e999`. Критерій — `window.__READY__`
настав. Знімати сторінку — skill `browser-verify`.

**Помилки тонуть у `try/catch`**, тож «помилок JS: 0» нічого не доводить: перевіряй
саме готовність сторінки. Так і знайшлося, що мій власний коментар проковтнув
`window.__READY__ = true;` у кінці рядка — три проби показали «мертва», зокрема
безневинна `?__proto__=1`.

Ворожі payload для полів — `tools/viewer-wasm/test/share.mjs` (у гілці
`share-view-links`): зразок того, як виглядає такий тест.

## Бекенд `tools/viewer.py`

Перевірено окремо, **джерелом проблем не є** — не переписуй його «про всяк випадок»:

- `do_GET` ріже `?` і порівнює шлях із переліком — файлів за шляхом не віддає,
  обходу каталогів немає; `?query` сервер не розбирає взагалі;
- `scad_literal()` бере тип зі схеми, `repr(float(v))` падає на нечислі, рядок мусить
  бути з `p['options']`, `subprocess.run` списком аргументів без shell;
- слухає `127.0.0.1`, у мережу не виходить;
- `export_static` робить `blob.replace('</', '<\\/')` перед вставкою в `<script>`.

## CSP

У зібраній WASM-сторінці, плагін Vite з `apply: 'build'` — у dev Vite вставляє власні
інлайн-скрипти, і політика зламала б `npm run dev`. `frame-ancestors` через `<meta>`
браузер ігнорує (це лише заголовок), а на GitHub Pages заголовків не поставити.

Наступний рубіж, якщо колись знадобиться: **Trusted Types**
(`require-trusted-types-for 'script'`) перетворює правило на помилку виконання —
присвоєння `innerHTML` рядка кидає виняток. Заважає те, що кілька місць подають у
`innerHTML` рядки з нашого словника (`data-i18n-html` із посиланнями): їх треба або
перевести на DOM, або завести іменовану політику. Примусово працює в Chromium.
