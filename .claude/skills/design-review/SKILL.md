# Перевірка конструкції

Workflow лежить у `.claude/workflows/design-review.js`. Це десятки хвилин роботи кількох агентів і сотні тисяч токенів, тому:

1. **Запускай лише з явної згоди користувача на багатоагентний запуск** (так вимагає інструмент Workflow) і спитай про залишок ліміту. Минулого разу перша спроба згоріла цілком: усі чотири рецензенти вперлись у ліміт сесії, результату — нуль.
2. Виклик: `Workflow({name: "design-review", args: {runName: "<РРРР-ММ-ДД-ГГХХ>", verify: "critical-major", maxVerify: 8}})`. Мітку часу передавай сам (`date +%Y-%m-%d-%H%M`), у скриптах workflow годинника немає. `verify: "none"` — якщо ліміту мало: рецензенти вже дають 90 % користі.
3. **Результати не губляться**: кожен агент перед поверненням пише JSON у `docs/reviews/<runName>/` (`review-<лінза>.json`, `verdict-NN-<лінза>.json`). Якщо workflow впав або його довелося зупинити — читай ці файли; запасний шлях — `journal.jsonl` у теці транскриптів запуску (рядки `type: "result"`).
4. Свої лінзи можна передати через `args.lenses = [{key, prompt}]`, контекст іншого вузла — через `args.context`.

## Що робити зі знахідками

- Зведи їх у таблицю: що підтверджено кількома рецензентами незалежно (це майже завжди правда), що спірне.
- Перед виправленням відтвори проблему числом або рендером: рецензенти помиляються рідше, ніж здається (минулого разу 5 із 5 перевірених підтвердились), але виправлення «наосліп» ламає геометрію.
- Після виправлень — чеклист зі skill `scad-mechanism`, нова версія, у README розділ «що змінено після перевірки» і що свідомо відкладено.
- Сирі результати лишаються в `docs/reviews/` — це джерело, не видаляй.
