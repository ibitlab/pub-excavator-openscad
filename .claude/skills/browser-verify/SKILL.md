# Перевірка сторінок у headless Chrome

Два інструменти, і між ними вибирають за питанням. `puppeteer-core` свідомо не в `package.json` (зауваження `npm audit` у його залежностях) — один раз: `npm i --no-save --prefix tools/media puppeteer-core`.

| питання | інструмент |
|---|---|
| «скільки, де, чи спрацювало» | `tools/media/probe.mjs` — друкує JSON |
| «як це виглядає» | `tools/media/page_shot.mjs` — знімок, кадри циклу |
| «чи розрізняються кольори, чи читається текст» | `tools/media/color.py` |

```
python3 tools/viewer.py --port 8791 &                       # або: cd tools/viewer-wasm && npx vite preview --port 8797 --strictPort &
node tools/media/page_shot.mjs http://127.0.0.1:8791/ --out /tmp/shot.png --view Ізометрія
```
Код виходу 3 (в обох) = на сторінці були помилки JS. Знімок обов'язково ВІДКРИЙ і подивись: «файл створено» нічого не доводить.

## Проба числом — замість одноразового скрипта

**Не пиши власний скрипт із `puppeteer.launch`.** Одна сесія коштувала 74 таких файлів (1830 рядків), де корисним був один рядок, а решта — однакова обгортка. Усе це тепер аргументи `probe.mjs`; кроки виконуються в порядку, у якому написані:

```
node tools/media/probe.mjs http://localhost:8797/ --js "__ONSCREEN__()"
node tools/media/probe.mjs URL --phone --tap "#warn_btn" --js "getComputedStyle(document.querySelector('#warn')).display"
node tools/media/probe.mjs URL --phone --fresh --tap "js:__ONSCREEN__().body" --js "__PICK__()"
node tools/media/probe.mjs URL --set sl_boom=40 --js "__VIEW__().angles" --shot "/tmp/x.png 0,0,372,330"
```

- `--phone` — 390×844, `isMobile`, `hasTouch`, dsf 2 і **справжній дотик** у `--tap`; без нього 1440×900 і миша.
- `--fresh` — окремий контекст, тобто порожній `localStorage`: мова, згорнуте попередження, лічильник підказки. Інакше перевіряєш не перший візит, а свій попередній запуск.
- `js:вираз` як ціль тапу — бо метал на екрані не там, де здається (див. `__ONSCREEN__`).
- Решта — у шапці файлу.

Кольори — `tools/media/color.py`: `de` (ΔE у CIE Lab, поріг 25, `--cvd` — очима дальтоніка), `contrast` (WCAG, 4.5/3.0), `px` (середній колір прямокутника знімка — координати в пікселях файлу, тобто вдвічі більші за CSS при `dsf 2`; потрібен `tools/.venv/bin/python`). Міряй ΔE **лише на парах, що справді сусідять** — на екрані або у вузлі; повний перебір дає гірші числа ні про що.

## Що сторінки віддають тестам

Гачки (є в обох сторінках, якщо не зазначено):

| гачок | що дає |
|---|---|
| `__READY__` | `true` після першої побудови моделі — чекати саме його |
| `__ONSCREEN__()` | `{tooth, axisE, body}` — екранні `[x, y]`; `body` = центр габариту ковша, **там метал** (лише WASM) |
| `__VIEW__()` | увесь ракурс: `angles`, камера, видимість, змінені параметри |
| `__SETVIEW__(v)` | застосувати такий об'єкт |
| `__CAM__()` | `{p, t, zoom}` — положення камери |
| `__PICK__()` | назва підсвіченого тіла або `null` (лише WASM) |
| `__PNG__()` | Blob знімка сцени (лише WASM) |
| `__SM__`, `__VJREPO__` | 3D-миша, список ракурсів із репозиторію |

Селектори: повзунки `#sl_boom` / `#sl_stick` / `#sl_bucket` (і поля `#num_*`), прапорці видимості `#tog_НАЗВА` (`cylinders linkage bucket post pins ground edges envelope kin` — останній лише в WASM), параметр моделі `#p_НАЗВА input`, канва `#c`, панель `#side`, HUD `#hud`, рядок стану `#status`.
Лише WASM: ручка шухляди `#grab` з кнопками `#fold_btn` `#warn_btn` `#lock`, картка попередження `#warn`, підказка `#tip`, індикатор рушія `#load`, легенда `#legend`, ряд видів `#views`, `#png`, `#lang`, `#adv_on`.
Стан розкладки — класи на `<body>`: `sheet0` (згорнута) / нічого (робоча) / `sheet2` (повна), `advon`, `dragging`.

## Дві мови (лише WASM-сторінка)

`tools/viewer-wasm/` двомовна, серверна сторінка — тільки українська. Мова: `?lang=en` → `localStorage` → `navigator.language` → `uk`. Після зміни сторінки перевіряй **обидві** мови і сам перемикач UK/EN: вся розмітка перемальовується без перезавантаження й БЕЗ перезапуску рушія — типова регресія в тому, що після перемикання зникає частина панелі або втрачається поза.

`--view` і `--toggle` шукають кнопку за текстом, тож підписи мають збігатися з мовою сторінки: `Ізометрія`/`Isometric`, `Збоку`/`Side`, `Ззаду-збоку`/`Rear-side`, `робоча зона`/`work envelope`.

Перевіряєш не «чи малюється», а «чи безпечно» — skill `web-safety`: там проби по адресі,
ворожі payload і ознаки зараження, які видно числом, а не оком.

## Граблі, на які вже наступали
- `--virtual-time-budget` НЕ чекає веб-воркерів: WASM-сторінка знімається на «Завантажую рушій…». Чекай `window.__READY__` (сторінки ставлять його після першої побудови).
- `--dump-dom` зависає на сторінці з безперервним `requestAnimationFrame`.
- WebGL у headless: `--enable-unsafe-swiftshader --use-angle=swiftshader`. Перші кадри після побудови сцени повільні — тести руху починай після паузи ≈1 с.
- Сервер `viewer.py` має відкидати `?…` з адреси (інакше 404); `vite preview` потребує попереднього `vite build`.
- `file://`: WebHID і модулі з CDN працюють, модульні воркери — ні (WASM-версія лише через http).
- Зміна поля параметра з тесту: відкрити `<details>` групи, потрійний клік у `#p_НАЗВА input`, ввести значення, чекати в `#status` «змінено параметрів: N».
- Підставні пристрої ставляться ДО скриптів сторінки (`evaluateOnNewDocument`): зразок — `tools/viewer-wasm/test/spacemouse.mjs` (Gamepad API і WebHID). Це перевіряє логіку, а не залізо — так і кажи користувачеві.
- **Зелений `npm test` не означає, що сторінка жива.** Smoke-тест звіряє спільні блоки й ключі i18n, але не завантажує сторінку цілком: одного разу з `tools/viewer/index.html` зникли 73 рядки (секція параметрів і `resize()`), а тест пройшов. Після правок у сторінках роби знімок — саме він показав `resize is not defined`.
- Після тестів зупини сервери (`pkill -f "viewer.py --port"`, `pkill -f "vite preview"`) і завислі `headless=new`.

## Дотик і телефонна розкладка

- `setPointerCapture` під емуляцією дотику НЕ тримає вказівник: жест губиться на першому ж русі. Слухачі `pointermove`/`pointerup` вішай на `window`, а не на елемент.
- Тап ≠ перетягування: сторінка рахує тапом рух ≤ 6 px. Тест, що «тягне» на 3 px, перевіряє не те.
- Ціль у сцені бери з `__ONSCREEN__()`. Точка між віссю E і зубом — **порожнеча всередині пащі ковша**, промінь там нічого не зустріне; для «влучити в ківш» є `body`.
- Буфер обміну в headless заборонений — кнопку «копіювати» перевіряй за станом сторінки, а не за вмістом буфера.
- Телефонна розкладка вмикається умовою `(max-width: 900px), (pointer: coarse)`. Поріг за самою шириною хибний: телефон лежачи — 844, планшет у портреті — 768.
- Після переходу між розкладками пропорція кадру інша, сторінка робить `setView(null)`; знімок одразу після зміни розміру застає старе вписування.

## Сторінка на папір: PDF і перевірка його сторінок

PDF робить Chrome, перевіряє poppler (`brew install poppler`; є в QUICKSTART). `mutool`,
`gs`, ImageMagick не потрібні.

- **PDF** — `to_pdf(html, pdf, chrome, підпис, дата)` з `print3d-parts/make_assembly_pdf.py`
  (імпортом, не копією): з `node` + `puppeteer-core` у `tools/media/node_modules` дає
  колонтитул із номерами сторінок, без них — `--print-to-pdf`. `@page { size: A4;
  margin: … }` + `preferCSSPageSize` → CSS-міліметри стають міліметрами паперу без
  масштабу: SVG `width="190mm" viewBox="0 0 190 277"` друкується рівно 1:1.
- **Сторінка PDF у картинку** — `pdftoppm -r 192 -png -f N -l N -singlefile файл.pdf out`
  (→ `out.png`). Перевіряй САМ PDF: розриви сторінок, колонтитули, картки, що не мають
  рватися, — це видно лише тут. `pdfinfo` дає кількість сторінок і формат
  (A4 = 595.28×841.89 pt; Chrome пише 594.96×841.92); `pdftotext -layout файл.pdf -`
  віддає текст зі сторінками через `\f` — так знаходиться сторінка за текстом шапки і
  перевіряється числом, що всі підписи в PDF є.
- **Запасний шлях без poppler** — знімок HTML однієї сторінки: `chrome --headless=new
  --disable-gpu --hide-scrollbars --force-device-scale-factor=2 --window-size=794,1123
  --screenshot=out.png file://…` (794×1123 = A4 при 96 dpi). Це проксі, не PDF: знімок
  бере лише перший екран, для N-ї сторінки треба окремий HTML лише з нею.
- **Масштаб перевіряється числом**: при 192 dpi 100 мм = 755.9 px, 190 мм = 1436 px —
  знайди у картинці найдовшу темну горизонталь (лінійка, лінія підвалу) і поділи.
- Картинки вбудовуй base64 (`data:image/png;base64,…`): HTML самодостатній, за `file://`
  сусідами Chrome не ходить. `break-inside: avoid` на картках, `break-before: page` на
  розділах, `thead { display: table-header-group }` повторює шапку таблиці.
- Розкладку документа перевіряй так само, як сторінки: спершу числа (JSON з координатами
  того, що намальовано), потім один знімок — skill `print-sheets` робить це для аркушів.

## Граблі розмітки, які видно лише знімком

Кожна з них проходить складання, тести й `grep` — і ламає сторінку мовчки:

- `#id` у CSS б'є `.class`: фон кнопки за id переважить `button.on`, і натиснутий стан стане білим по світлому. Або пиши `#id:not(.on)`, або не давай фон за id.
- `replaceChildren()` знищує вкладені елементи, які туди поклав інший код; наступний `getElementById` дає `null`, а `appendChild(null)` валить сторінку. Тримай такі вузли у змінній і повертай на місце в тій же функції, що перебудовує вміст.
- `data-i18n` на батьківському елементі стирає все вкладене при перемиканні мови — текст загортай у власний `<span data-i18n=…>`.
- Збіг імен класів: нова `.bar` успадкувала `flex: 1` від смужки циліндра й розтяглася через пів панелі.
- Абсолютний блок із `left: 50%; transform: translateX(-50%)` без `width: max-content` стискається до половини ширини.
- Vite переписує `new Worker(new URL('./x.js', import.meta.url))` як **цілий вираз** — винесеш URL у змінну, і шлях зламається. Потрібен окремий URL — `import url from './x.js?worker&url'`.
- Коментар `//` наприкінці рядка ковтає наступний оператор, якщо той дописали в той самий рядок: так зникав `window.__READY__ = true`.
