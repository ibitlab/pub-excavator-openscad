# Збирання версії

```
tools/build_version.sh "що змінено"            # нова тека versions/VNNN-РРРР-ММ-ДД-ГГХХ/ (≈20 с)
tools/build_version.sh --commit "що змінено"   # те саме + git add -A і коміт "VNNN: що змінено"
```

Скрипт по черзі: перевіряє перекриття пластин (зупиняється, якщо є) → експортує STL → рендерить положення та вузли → **підрізає поля рендерів** → креслення робочої зони (`tools/work_range.py`, дві мови) → генерує звіти → специфікацію, DXF і PDF (через `tools/bom_drawings.sh`) → знімок моделі та скриптів → `VERSION.md` → оновлює картинки README у `docs/img/`.

## `--render=cgal` обов'язковий у КОЖНОМУ рендері

Без нього OpenSCAD малює прев'ю (OpenCSG), а в прев'ю **поверхні деталей, що дотикаються, пробивають одна одну**. На стрілі труба малювалася поверх накладки перелому, і вежа F виглядала так, ніби стоїть у повітрі над трубою. Геометрія при цьому ціла: зріз показує труба −60…60, накладка 60…68, основа вежі рівно 68, а `intersection()` кожної пари дає нуль.

Помилка небезпечна саме тим, що картинка виглядає правдоподібно — її не відрізнити від справжнього дефекту, і на ній можна «побачити» проблему, якої немає, або не побачити справжню. З бекендом Manifold `--render` майже безкоштовний: усі 13 рендерів версії — 7 секунд.

**Саме `--render=cgal`, а не голий `--render`.** Прапорець бере НЕОБОВ'ЯЗКОВИЙ аргумент: поставиш його останнім перед іменем файлу — він з'їсть ім'я, openscad надрукує usage і мовчки нічого не зробить. З `=cgal` порядок аргументів більше не має значення.

Перевірити, чи не бреше картинка: відрендерити ту саму камеру окремо для двох деталей, накласти маски й подивитися, чи збігається видиме з очікуваним.

## Підрізка полів (`tools/trim_png.py`)

`openscad --viewall` вписує в кадр не деталь, а її габаритну **сферу**: довга тонка стріла займала 16 % кадру, решта — тло. Тому рендери робляться більшими (2400×1500) і підрізаються по вмісту.

- **Пози крайніх положень (`folded`, `max_reach`, `dig_deep`, `max_height`) ріжуться `--common`** — однією рамкою на всіх. Незалежна підрізка дала б кожній свій масштаб, і чотири картинки перестали б бути порівнянними між собою.
- `side_default`, `part_*`, `iso_default`, `envelope` ріжуться кожен по собі: їх ні з чим не зіставляють (колаж поз медіа-набору береться зі знімків сторінки, а не з цих рендерів).
- Додаєш рендер — вирішуй, у який із двох списків він потрапляє. Потрапив не в той — або втратиш масштаб, або лишиш пів кадру білим.

## Крупні плани кріплень (`part_*_mount.png`)

Другий ракурс кожного вузла для `print3d-parts/ASSEMBLY.md`: на загальному виді вуха ковша, вежа F і вилка D ховаються за корпусом, а саме їх найважче поставити правильно. Камери **з фіксованою відстанню** — це навмисне наближення, тому `--viewall` тут немає і кадр НЕ підлаштується під зміну геометрії.

**Труба в крупному плані виходить за кадр — так і має бути. Кронштейн — ні.** Розрізнити це на око важко, а підрізка полів зрізаного кадру не виявить: він виглядає як нормальний. Тому скрипт рендерить ті самі камери з САМИМИ кронштейнами (`boom_gussets`, `boom_bracket_D/F`, `stick_cheeks`, `stick_bracket_H`, `bucket_ears`) і проганяє `tools/trim_png.py --edges`: той каже, чи геометрія торкається краю кадру. Торкнулася — камеру треба виправити.

Той самий `--edges` корисний і окремо. А `tools/trim_png.py --report docs/img/*.png` дає таблицю на всі картинки — розмір, заповнення кадру, зрізані краї, порожні рендери. **Це замінює десяток відкритих картинок**: майже всі питання про рендер («не порожньо? не зрізано? не половина кадру біла?») числові. У крупних планах `--report` штатно пише «ЗРІЗАНО»: труба там і має виходити за кадр, тому вирок виносить `--edges` по групах кронштейнів, а не `--report` по готовій картинці.

## Правила

- **Усе згенероване живе тільки у `versions/`.** У корені лежать джерела (`scad/`, `tools/`, `docs/01-design-inputs.md`, `docs/research/`) і `docs/img/` для README. Не клади копії звітів чи рендерів у корінь: вони непомітно застарівають. Актуальна версія — тека з найбільшим номером.
- Згенеровані файли не редагуються вручну: зміни вносяться в модель або скрипт, потім нова версія.
- `--commit` комітить **усе** змінене (`git add -A`). Перед прапорцем переконайся, що нічого особистого не лежить поза `temp/` (вона в `.gitignore`); якщо потрібен вибірковий коміт — збирай без прапорця.
- README посилається на `drawings/parts.pdf` і `dxf/` останньої версії: `build_version.sh` сам переписує шлях
  `versions/VNNN-…/` в обох README на нову теку. Прев'ю PDF і тур сторінки в README — не тут, а
  `tools/media/readme_media.sh` (запускати, коли змінились сторінка, вигляд машини чи PDF).
- Тестові чи порожні версії краще не плодити: якщо змінювався лише текст README, версія не потрібна.
- У `VERSION.md` і звіти скрипт вставляє застереження про ШІ (`WARN` у `build_version.sh`, текст-джерело — `SAFETY.md`). Не прибирай його: теки версій ходять окремо від README.
- `docs/01-design-inputs.md` пишеться вручну; якщо його немає, скрипт друкує «пропущено» і йде далі — це не помилка.
- Рендери робляться з `--viewall --autocenter`: із фіксованою камерою кадр обрізав ківш і колону.
- Перший запуск на новій машині створює `tools/.venv` (matplotlib для PDF, shapely для `tools/bucket.py`); потрібні `openscad` у PATH і `python3`.

## Після збирання

Відкрий `viewer.html` нової версії (3D, кути рухаються) або запусти `tools/viewer.sh`. Переглянь `VERSION.md`, `docs/overlaps.txt` і `docs/motion.txt` (рухомі пари) нової версії, `docs/05-bucket.md` (зазори й міцність ковша), найменші запаси у `docs/03-strength.md`, КОЖНУ сторінку ескізів труб і нових пластин (`drawings/png/`), і хоча б один рендер вузла та одну сторінку ескізів (`drawings/png/`) очима — скрипт не знає, чи картинка має сенс.
