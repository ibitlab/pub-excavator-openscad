# Збирання версії

```
tools/build_version.sh "що змінено"            # latest/: нова версія або оновлення на місці (≈2 хв, + ≈1 хв набір)
tools/build_version.sh --new "що змінено"      # примусово нова версія, навіть без змін по суті
tools/build_version.sh --commit "що змінено"   # те саме + два коміти: "Archive VNNN…", потім "VNNN: що змінено"
```

Скрипт по черзі, усе в `build/version/`: перевіряє перекриття пластин і рухомі пари, звіряє Python-двійники з моделлю (`tools/check_twins.py`; будь-що з цього зупиняє збирання) → експортує STL → рендерить положення та вузли → **підрізає поля рендерів** → креслення робочої зони (`tools/work_range.py`, дві мови) → генерує звіти → знімок моделі та скриптів → `VERSION.md` → **порівнює з `latest/`** (`tools/compare_build.py`) → специфікацію, DXF і PDF з остаточною назвою (через `tools/bom_drawings.sh`) → кладе в `latest/` → оновлює картинки README у `docs/img/` (сторінку ескізу — `tools/copy_if_changed.py`: лише якщо змінилось креслення, а не шапка з датою) → після нової версії збирає набір (`print3d-parts/make.sh`, підверсія `VNNN.1`).

## Нова версія чи оновлення на місці

`tools/compare_build.py latest build/version` звіряє суть: STL — за набором трикутників, звіти й діапазони з `VERSION.md` — текстом без номерів, дат, застережень і підписів.
- **Змінилось** (геометрія, числа звітів, діапазони) → нова `VNNN`: колишній `latest/` разом із набором і його історією переїжджає `git mv` у `versions/<його назва>`. Номер — наступний після найбільшого серед `versions/`, `latest/` і git-тегів `VNNN` (V002–V005 — лише теги, їхні номери не видаються вдруге).
- **Не змінилось** (кольори, рендери, стиль PDF, текст застереження) → `latest/` оновлюється на місці: назва та сама, у `VERSION.md` додається рядок «Оновлено: дата — опис», набір не чіпається. `--new` — примусово нова версія (так зроблено V006: геометрія та сама, що з V001, а структура нова).
- STL з тими самими трикутниками в іншому порядку копіюються зі старого `latest/` байт-у-байт (`--settle`) — git не бачить «зміни», де її немає.

## `--render=cgal` обов'язковий у КОЖНОМУ рендері

Без нього OpenSCAD малює прев'ю (OpenCSG), а в прев'ю **поверхні деталей, що дотикаються, пробивають одна одну**. На стрілі труба малювалася поверх накладки перелому, і вежа F виглядала так, ніби стоїть у повітрі над трубою. Геометрія при цьому ціла: зріз показує труба −60…60, накладка 60…68, основа вежі рівно 68, а `intersection()` кожної пари дає нуль.

Помилка небезпечна саме тим, що картинка виглядає правдоподібно — її не відрізнити від справжнього дефекту, і на ній можна «побачити» проблему, якої немає, або не побачити справжню. З бекендом Manifold `--render` майже безкоштовний: усі 13 рендерів версії — 7 секунд.

**Саме `--render=cgal`, а не голий `--render`.** Прапорець бере НЕОБОВ'ЯЗКОВИЙ аргумент: поставиш його останнім перед іменем файлу — він з'їсть ім'я, openscad надрукує usage і мовчки нічого не зробить. З `=cgal` порядок аргументів більше не має значення.

Перевірити, чи не бреше картинка: відрендерити ту саму камеру окремо для двох деталей, накласти маски й подивитися, чи збігається видиме з очікуваним.

## Підрізка полів (`tools/trim_png.py`)

`openscad --viewall` вписує в кадр не деталь, а її габаритну **сферу**: довга тонка стріла займала 16 % кадру, решта — тло. Тому рендери робляться більшими (2400×1500) і підрізаються по вмісту.

- **Пози крайніх положень (`folded`, `max_reach`, `dig_deep`, `max_height`) ріжуться `--common`** — однією рамкою на всіх. Незалежна підрізка дала б кожній свій масштаб, і чотири картинки перестали б бути порівнянними між собою.
- `side_default`, `part_*`, `iso_default`, `envelope` ріжуться кожен по собі: їх ні з чим не зіставляють (колаж поз медіа-набору береться зі знімків сторінки, а не з цих рендерів).
- Додаєш рендер — вирішуй, у який із двох списків він потрапляє. Потрапив не в той — або втратиш масштаб, або лишиш пів кадру білим.

## Правила

- **Усе згенероване живе тільки в `latest/` і `versions/`**, проміжне й PNG-прев'ю — у `build/` (не в git). У корені лежать джерела (`scad/`, `tools/`, `docs/01-design-inputs.md`, `docs/research/`) і `docs/img/` для README. Не клади копії звітів чи рендерів у корінь: вони непомітно застарівають.
- Згенеровані файли не редагуються вручну: зміни вносяться в модель або скрипт, потім нова версія.
- `--commit` комітить **усе** змінене (`git add -A`) — другим комітом; перший («Archive …») бере лише проіндексоване `git mv`. Перед прапорцем переконайся, що нічого особистого не лежить поза `temp/` (вона в `.gitignore`); якщо потрібен вибірковий коміт — збирай без прапорця і коміть сам так само двома кроками: спершу проіндексоване перейменування, потім решту.
- **Порядок: спершу версія, потім набір.** `print3d-parts/make.sh` відмовиться збирати, якщо модель не збігається з `latest/scad/` — після зміни моделі набір збирає сам `build_version.sh`.
- README посилається на `latest/…` — шляхи сталі, переписувати нічого не треба. Прев'ю PDF і тур сторінки в README — не тут, а
  `tools/media/readme_media.sh` (запускати, коли змінились сторінка, вигляд машини чи PDF).
- Тестові чи порожні версії не плодити: якщо змінювався лише текст README, збирати не треба; косметику скрипт сам оновить на місці. Перевіряти сам механізм збирання — в окремому `git worktree`, не в головному дереві.
- У `VERSION.md` і звіти скрипт вставляє застереження про ШІ (`WARN` у `build_version.sh`, текст-джерело — `SAFETY.md`). Не прибирай його: теки версій ходять окремо від README.
- `docs/01-design-inputs.md` пишеться вручну; якщо його немає, скрипт друкує «пропущено» і йде далі — це не помилка.
- Рендери робляться з `--viewall --autocenter`: із фіксованою камерою кадр обрізав ківш і колону.
- Перший запуск на новій машині створює `tools/.venv` (matplotlib для PDF, shapely для `tools/bucket.py`); потрібні `openscad` у PATH і `python3`.

## Після збирання

Відкрий `latest/viewer.html` (3D, кути рухаються) або запусти `web/viewer.sh`. Переглянь `VERSION.md`, `docs/overlaps.txt` і `docs/motion.txt` (рухомі пари) нової версії, `docs/05-bucket.md` (зазори й міцність ковша), найменші запаси у `docs/03-strength.md`, КОЖНУ сторінку ескізів труб і нових пластин (`build/drawings-png/` — PNG сторінок у версію не йдуть, вміст той самий, що в `drawings/parts.pdf`), і хоча б один рендер вузла та одну сторінку ескізів очима — скрипт не знає, чи картинка має сенс.
