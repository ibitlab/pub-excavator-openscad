# Аркуші розкладки 1:1 (`print3d-parts/sheets/`)

Це **не** інструкція-текст (та лишилась у `ASSEMBLY.md`/`ASSEMBLY.pdf`, її не чіпати),
а папір проти купи схожих деталей: деталь кладеться на свій контур 1:1 — збіглася,
значить вона. Формат користувачеві подобається; розвивати саме його.

```
tools/.venv/bin/python print3d-parts/sheets/make_sheets.py --png      # усе: SHEETS.pdf + sheets.json + png/ (≈1.5 хв)
… --only 3 --no-steps --no-pdf --png                                    # один аркуш без кроків — для ітерацій (≈10 с)
… --fresh                                                                # перерендерити всі PNG (кеш у $TMPDIR/p3d_sheets)
```
`print3d-parts/make.sh` запускає генератор сам, після STL і перед `stl/group.sh`.

| Файл | Що це |
|---|---|
| `make_sheets.py` | генератор: силуети зі STL (shapely), комірки, пакування, рендери, виноски, HTML → PDF |
| `sheets.scad` | обгортка рендерів: підключає `../parts.scad` (а той — модель як бібліотеку), фарбує деталі |
| `SHEETS.pdf` | 6 аркушів розкладки + сторінки кроків (18 стор.) |
| `sheets.json` | **усі числа**: комірки, ракурси, пікселі кожної деталі, виноски, кроки — читати його, не PDF |
| `png/N_slug.png` | прев'ю аркушів розкладки з САМОГО PDF (`pdftoppm`, сторінка знаходиться за текстом шапки через `pdftotext`); без poppler — знімок HTML. Латинські назви, бо на них посилаються README |

## Що вирішено (не перевідкривати)

- **Аркуш = вузол з `assembly.tsv`** («1. Стріла» … «7. Складання на пальцях»); склад,
  порядок і тексти «куди/як» беруться звідти, назви файлів і кількості — з `parts.tsv`.
  Колона й циліндри — на одному аркуші, коромисло й тяга — на одному. Нову деталь
  досить вписати в обидві TSV — на аркуш вона потрапить сама.
- **Одна комірка = один файл.** Однакові плоскі деталі (`×N стосом`) — один контур,
  кладуться одна на одну; пальці — кожен окремо (вони й так по одному на файл).
- **Як лежить деталь** — так, як друкується (орієнтація з `parts.tsv` уже кладе
  найбільшу грань на стіл), крім пальців: друкуються стоячи, на папері лежать.
  **Обичайку ковша користувач хоче боком, профілем** — дном вона дає лише
  прямокутник. Не «покращувати» на найбільшу грань.
- **Підписи в комірці**: номер кроку + файл (+`×N`), коротка назва, габарит × h,
  отвори (великі — Ø просто всередині отвору, малі — в рядку), для кілець Ø/Ø·h,
  для пальців Ø×L і голівка. Пари з однаковими габаритами (±0.3 мм) отримують
  `= файл (однакові)`, з різницею < 1 мм — `≈ файл: чим різняться`. Рядок «куди»
  з комірки прибрано — він на картці кроку, а місце на аркуші дорожче.
- **Пакування** — MaxRects трьома евристиками × трьома порядками, береться розкладка
  з найбільшим суцільним вільним прямокутником (туди стають рендери). Аркуш стріли
  заповнений комірками на ~80 %, тому туди влазить один рендер, другий іде на сторінку
  кроків — це норма, а не помилка.
- **Рендери**: у `sheets.scad` i-та деталь зі списку `keys` фарбується в hue = i·360/n;
  зовнішній `color()` у прев'ю OpenSCAD перекриває внутрішні, тому модель не змінюється.
  Виноска ставиться на піксель того відтінку, **найближчий до центроїда** (сам центроїд
  у дзеркальної пари падає в порожнечу між половинками). Тло — колір кутового пікселя,
  сірі деталі кроків (S ≈ 0) у маски не потрапляють.
- **Ракурси не підбираються руками**: з 8 кандидатів (rotx 55/125 × rotz 25/115/205/295)
  беруться два за покриттям деталей у пікселях (перший — згори). Картка кроку — основний
  ракурс; якщо нову деталь на ньому майже не видно (< 400 px), береться кандидат, де
  її видно найбільше. Деталь без виноски на жодному ракурсі → «УВАГА» у виводі.
- **Пальці на плані всієї машини — дві крапки** (40–60 px), тому в огляді вони
  потовщені (`fat=true` в обгортці), а картки кроків для них — **крупні плани
  шарнірів**: центри з `echo(PINPOS)` обгортки, `--camera=центр,кути,700` без `--viewall`.
- **1:1 тримається на CSS-міліметрах**: SVG `width="190mm"` + `viewBox` у мм, Chrome
  друкує з `preferCSSPageSize`. На кожному аркуші лінійка 100 мм — перевірка принтера.
  Перевірено числом: у прев'ю при 192 dpi лінія 190 мм = 1436 px.
- **PDF** робиться тим самим `to_pdf` з `make_assembly_pdf.py` (Chrome; номери сторінок —
  через `node` + `puppeteer-core` у `tools/media`). Нових залежностей не додано.

## Як розширювати

- **Нова деталь у наборі** → рядки в `parts.tsv` і `assembly.tsv`; більше нічого. Якщо
  вона кругла або будується в `parts.scad`, а не дістається з вузла через `$sel`, —
  перевір, що на рендері вузла її видно: `sheets.scad` малює деталь через
  `{ $sel = k; part_by_name(вузол); }`, тож у моделі має бути `sel("k")` саме з цим
  ключем (так уже є для всіх втулок і бобишок). Труби й плити колони мають окремі
  гілки в `node_part()`.
- **Новий вузол** → запис у `SHEETS` (slug латиницею, заголовок, підзаголовок, вузли з
  `assembly.tsv`, рендери), за потреби `RENDER_KEYS` (які ключі малює який рендер) і
  `node_of()` у `sheets.scad` (у якій системі координат моделі його брати).
- **Новий тип рендера** (як `pins` чи `cyl`) — гілка в `sheets.scad`; якщо йому потрібні
  змінні моделі (`show_ground` тощо) — лише через `-D` у `RENDER_EXTRA`: змінні моделі
  читаються з її власної області, з обгортки їх не перекрити.

## Граблі

- **Headless OpenSCAD зрідка падає мовчки** (rc ≠ 0, порожній stderr, файлу нема) — рендер
  повторюється до трьох разів; не «лікувати» це інакше.
- **`--view=edges` у headless прев'ю не малює нічого.** Межі між деталями домальовуються
  з міток пікселів (де мітка сусіда інша) — інакше на чорно-білому папері форма зникає.
- `!!! невідома деталь: none` модель каже завжди при `part="none"` — це не помилка,
  фільтрується. Справжні — `ERROR|WARNING:` і інші `!!!`.
- **Ширина тексту оцінюється** (≈ 0.55 em на знак), не міряється: довгий підпис робить
  комірку ширшою за контур. Скорочуй тексти (коротка назва обрізається до 34 знаків),
  а не «підганяй» коефіцієнт під один випадок.
- **Порожнє поле в TSV** зсуває колонки (таби злипаються) — «нема значення» = `-`;
  `read_tsv` падає, якщо колонок не стільки, скільки очікує.
- Не тримай кириличних назв у `png/`: README посилаються на них шляхом.

## Перевірка після змін — числом, потім одним оком

1. `--only N --no-steps --no-pdf --png` для ітерацій; повний запуск наприкінці.
2. Читай `sheets.json`: кожна комірка в межах `[0,190]×[0,268]`, без перекриттів
   (перевірка — десяток рядків на Python), `uncovered` порожній, у `steps` немає
   `px` < 300, `renders_overflow` лише там, де аркуш справді повний.
3. Стандартний вивід: «УВАГА» про деталь без виноски або крок, де деталь не видно.
4. Лише тоді — один погляд на `png/` того аркуша, який змінювався. Кожен перегляд
   картинки коштує як кілька сотень рядків коду.
